# NVIDIA Isaac Sim / OmniLRS integration

The local simulator (`astraeus/`) is the reference implementation: fast,
deterministic, and the only path exercised by this repository's tests. The
`isaac/` layer runs the *same* disturbance vectors, the *same* seeds, and the
*same* outcome rules inside NVIDIA Isaac Sim so that estimates can be compared
across simulators and worst cases found locally can be replayed with a
physically based renderer and PhysX contacts.

> **Status.** Isaac Sim, ROS 2 and OmniLRS are not installed in this repository's
> CI. Everything under `isaac/astraeus_isaac/` (scene mapping, outcome monitor,
> CSV logging, terrain export) is unit-tested without Isaac. The entrypoints
> `standalone_env.py` and `omnilrs_bridge.py` are syntax-checked only; their
> Isaac/ROS API calls have been written against Isaac Sim 4.x
> (`isaacsim.SimulationApp`, `omni.isaac.core`) with a 2023.x fallback import,
> and must be smoke-tested on a machine with Isaac Sim before a campaign. The
> ROS 2 topic map ships with `verified: false` for the same reason.

## Layout

```
isaac/
  astraeus_isaac/          Isaac-free helpers (importable and tested anywhere)
    scene.py               x -> SceneParams (friction, light rotation, lux, fog)
    monitor.py             EpisodeMonitor (same outcome rules as astraeus.rover), GoalSeekController
    log.py                 EpisodeLog: append-only, fsync'd CSV in the ingest schema
    export.py              same procedural terrain as astraeus.terrain -> heightfield / OBJ / rocks JSON
  configs/
    lunar_scene.yaml       renderer, physics, rover USD or proxy, camera, output paths
    campaign.yaml          sampling mode (proposal | prior:Pk | replay:run.npz), episode budget
    ros2_topics.yaml       OmniLRS topic names/types + load-time YAML keys; `verified` flag
  standalone_env.py        Isaac Sim standalone app: builds the scene per episode, drives, logs
  omnilrs_bridge.py        ROS 2 node driving an already-running OmniLRS scene
  discover_topics.py       diff `ros2 topic list -t` against ros2_topics.yaml; --write marks verified
  export_terrain.py        CLI: export one episode's terrain for external tools
  batch_run.sh             stratified OmniLRS batches for load-time dims (k_soil, theta_r, slope_deg)
```

## How the eight dimensions map into Isaac Sim

| Dim | Isaac Sim representation | Fidelity note |
|---|---|---|
| `k_soil` | Recorded in `SceneParams.terramechanics_k_soil` and passed to `Rover.apply_terramechanics()` hook. | **Not modelled by rigid PhysX.** No sinkage, slip-sinkage or bulldozing without a wheel-soil plugin. The CSV `simulator` column says `isaac-standalone/rigid` so rows are never confused with local rows. |
| `theta_r` | `PhysicsMaterial` static/dynamic friction `μ = tan θ_r` on the terrain mesh. | Captures traction limit on slopes; not the shear-displacement (Janosi) transient. |
| `r_terrain`, `slope_deg`, `rho_rock` | Terrain mesh and rock prims generated by `astraeus_isaac.export` from the same `(x, seed)` as the local run — identical DEM, identical rock list. | Exact. |
| `sun_e`, `sun_psi` | `UsdLux.DistantLight` rotation from `distant_light_rotation_xyz`; intensity 128 klux. | Exact geometry. |
| `tau_dust` | Light intensity × `exp(-1.3 τ)`; scene fog density ∝ τ; camera exposure from `lunar_scene.yaml`. | Approximates suspended dust and veiling glare; lens-deposited dust would need a post-process. |

## Running the standalone environment

Inside the Isaac Sim Python environment (`./python.sh` in the Isaac install):

```bash
# 200 episodes drawn from the proposal q -> rows enter the weighted estimates after ingest
./python.sh isaac/standalone_env.py --episodes 200 --mode proposal --csv isaac/out/log.csv

# replay the (x, seed) pairs of a local campaign for cross-simulator comparison
./python.sh isaac/standalone_env.py --mode replay:runs/c1.npz --episodes 50

# one episode with the viewport open and RGB frames dumped
./python.sh isaac/standalone_env.py --episodes 1 --no-headless --write-frames
```

Then, on the local side:

```bash
python -m astraeus ingest runs/c1.npz isaac/out/log.csv                    # trust each row's source column
python -m astraeus ingest runs/c1.npz isaac/out/log.csv --source external  # force replay/ranking only
python -m astraeus report runs/c1.npz
```

By default `ingest` trusts the `source` column written by the Isaac side (`0`/`mc`,
`1`/`cem`, `2`/`external`; a blank cell means external). `--source external` forces
`source=2`; `--source proposal` asserts every row was drawn i.i.d. from `q`. Only
`source=0` rows enter importance-weighted estimates.

### Rover model

`lunar_scene.yaml: rover.usd_path` may point to your rover articulation
(wheel joint names in `wheel_joint_names`). When blank, a rigid-body four-wheel
proxy with VIPER-class dimensions (430 kg, R 0.25 m wheels, 1.8 × 1.4 m
footprint, 0.30 m clearance) is built in USD. Both are driven with the same
proportional controller as the local rover (`GoalSeekController`).

### Localisation

`controller.gt_pose: true` uses the PhysX pose directly (oracle localisation;
dust and lighting then cannot cause `nav_miss`). `false` integrates a drift
proxy `vo_drift_per_m · (1 − V)` onto the true pose, mirroring the local model.
The CSV `gt_pose` column records which was used.

## Running against OmniLRS through ROS 2

1. Launch OmniLRS (Lunaryard scene) with ROS 2 enabled.
2. Verify the topic map — **this step is mandatory**:
   ```bash
   python isaac/discover_topics.py                 # diff live topics vs configs/ros2_topics.yaml
   python isaac/discover_topics.py --write         # sets verified: true only on a complete match
   ```
   Names and types in `ros2_topics.yaml` were transcribed from the OmniLRS
   source and the original harness, not from a live simulator. If your OmniLRS
   version differs, edit the YAML until `discover_topics.py` passes. The bridge
   refuses to run while `verified: false` unless `--i-know` is passed.
3. Run:
   ```bash
   python isaac/omnilrs_bridge.py --episodes 50 --mode proposal
   ```

### Load-time dimensions and stratified batches

OmniLRS reads soil stiffness, friction angle and regional slope from YAML at
launch. They cannot vary per episode, so `batch_run.sh B N` draws `B` vectors
for `(k_soil, theta_r, slope_deg)`, rewrites the sim YAML (`batch_yaml.keys`
in `ros2_topics.yaml`), relaunches OmniLRS per batch, and lets the bridge vary
the remaining five dims live for `N` episodes with `--fixed k_soil=… theta_r=… slope_deg=…`.

Rows from such a design are **not** i.i.d. draws from `q`. The bridge marks
them `source=2`; the default ingest keeps that tag (or force it with `--source external`). They are valid for
replay, ranking and cross-simulator comparison, and for the stratified
estimator described in RESEARCH.md if you supply the batch weights yourself.

## Exporting terrain for other tools

```bash
python isaac/export_terrain.py --x slope_deg=9 rho_rock=6 --seed 17 --out isaac/out/terrain
python isaac/export_terrain.py --run runs/c1.npz --episode 379 --out isaac/out/terrain
```

writes `heightfield.npy`, `terrain.obj`, `rocks.json`, `craters.json` and
`meta.json` at 0.10 m resolution. The same function is what `standalone_env.py`
calls per episode.

## CSV schema

Written by `astraeus_isaac.log.EpisodeLog`, read by `Campaign.ingest_csv`:

```
k_soil theta_r r_terrain rho_rock slope_deg sun_e sun_psi tau_dust
index seed outcome source t_end final_dist max_tilt_deg max_slip max_sinkage
min_visibility mean_visibility vo_error severity simulator controller gt_pose wall_s batch_id
```

Rows are flushed and `fsync`'d after every episode so an overnight run that
dies keeps everything up to the last completed episode; a restarted run
resumes numbering from the existing file.

## Known gaps

* No sinkage/entrapment in rigid PhysX; `stuck` will be under-reported
  relative to the local Bekker model until a terramechanics plugin is wired
  into `Rover.apply_terramechanics()`.
* Isaac Sim API surface is version-sensitive; imports are isolated in
  `IsaacScene._isaac_imports` for that reason.
* Topic map unverified in CI (see above).
* No automated frame comparison between the local renderer and Isaac's
  RTX output; they are different renderers of the same geometry, not the same
  image.
